01 · Overview

设计立场

原版 IA 把「动作」（寻呼/对讲/点播/任务/快捷）做 Tab，用户每次都得重新选终端。v4 把终端提为一等公民，「广播」聚合三种动作，形成「找 → 做 → 自动 → 兜底」的清晰心智。

信息架构 5 tabs · entity-first

找
dvr终端
总览（列表 / 分区 / 地图）· 长按多选 → 直接派发动作
做
campaign广播
顶部三档：寻呼 / 对讲 / 点播 — 目标终端共享
自动
auto_awesomeAI
一句话搞定运维：迁移 / 周对调 / 取消 / 新建作息
自动
event_available任务
今日时间轴 + 作息方案 + 临时任务入口
兜底
support_agent服务
系统健康度 + AI 故障诊断 + 工单
主要差异 vs v2： 「快捷」下线 → 被 AI 取代；「对讲」从主导航降级到广播 Tab 内的一档；新增「终端」作为主入口；新增「服务」做兜底。

目标用户与场景

主用户

校园广播管理员（教师 / 总务）· 移动办公为主 · 偶尔在电脑上做批量配置。

核心场景

① 临时广播通知（5 秒内开口）
② 课间放音乐（按分区点播）
③ 检查故障 / 上报售后
④ 调整作息（学期开学 / 临时停课）

按屏规格

每张卡片包含：目的 · 关键状态 / 变体 · 交互规则 · 数据 / API · 导航。优先级 P0 = 主流程必做；P1 = 二级页 / 后续。

00

闪屏 + 登录

App 启动 → 闪屏（≤1.5s）→ 检查 token → 登录 / 主页
P0Auth
m-screens-1.jsx
SplashScreen
LoginScreen
状态 / 变体
  • Splash 默认 — 品牌渐变背景 + Logo + 版本号
  • Login 默认 — 账号 + 密码 + 记住我 + 服务器地址折叠区
  • Login error — 输入框红边 + 红色提示文案；保留已输入值
数据 / API
  • POST /auth/login → JWT (24h) + refresh token (30d)
  • 本地存储：account / server URL（密码不存）
交互规则
  • Splash 最短显示 800ms（防闪烁）· 最长 1500ms
  • 失败 3 次 → 强制输入图形验证码（接入 captcha）
  • 服务器地址默认折叠；点 chevron 展开
  • 密码框右侧 visibility icon 长按可见
导航
  • 登录成功 → 首页（默认 终端 Tab）
  • Token 失效 → 跳回登录页，保留 deep link

状态 / 变体
  • 默认 — 分区卡片折叠；显示统计数字 + 3 颗动作 icon
  • 某分区展开 — 展开后内含 3 列终端瓦片；可选单台

交互规则
  • 点击分区卡 → 展开/折叠（accordion）
  • 点击分区动作 icon → 跳广播 Tab 并预选该分区
  • 长按终端 / 分区 → 进入 bulk 多选态
  • 多选态： 顶部出"已选 N · 完成" · 底部 FAB-bar 永远 3 个动作（寻呼 / 对讲 / 点播）
  • 多选混合分区 允许；提交时合并目标终端去重
  • 点终端瓦片 → 详情页（音量 / 历史 / 网络）
  • 顶部 map icon → 地图视图（v4.1 实现）
导航
  • 入 → 任何一级 Tab 默认页
  • 出 → 广播 Tab / 终端详情 / 分区详情

04

AI 助手（一级 Tab · 中心抬起）

一句话搞定运维：任务迁移 / 周对调 / 取消 / 新建作息。占位 + 4 个完整子屏。

P0 占位
  • 暗色渐变背景 + 大输入框 + 提示气泡（"试试：把下周一的早会挪到周二"）

交互规则

  • 每条操作可一键撤销（24h 内）
数据 / API

层级表现恢复

离线策略

本应用严重依赖在线（广播 / 对讲 / 点播都需要联网）。离线时：

  • 所有"动作类"按钮 disabled，给"离线，不可用"提示
  • 仍可查看缓存的：终端列表（标灰 + 最后同步时间）、作息方案、工单列表
  • 登录页：检测到网络后自动重连

给 Claude Code 的注意事项：
  1. JSX 中的颜色 / 数值是设计真值，移植时用 token 命名引用（Compose 用 MaterialTheme 扩展，不要写死 hex）。
  2. "播放波形" / "脉动呼吸" 这类装饰动效在 HTML 是 CSS keyframes；移植到 Compose 用 InfiniteTransition。
  3. 占位屏（AI / 服务）的功能暂不接入，UI 落地优先；AI / 售后的完整流程作为 P1。
  4. 底部 TabBar 中央抬起项不要用 BottomNavigation 默认行为；自定义布局，中间项 56×56 +16 上抬。
