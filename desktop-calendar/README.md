# 本地日历 / 待办面板

按 `docs/design-handoff.md`（交接文档原文）实现的单窗口本地日历面板，980 × 620，纯本地、无服务端。

技术栈：**React 18 + TypeScript + Vite**，桌面外壳用 **Tauri 2**。

选这套的原因：本仓库原有的是 `AeroRadioControl` 那个 Android 工程（Java / minSdk 19），跟桌面日历没有可复用的组件或样式约定，所以按交接文档自己的指引「没有代码库就选定框架，纯本地桌面应用推荐 Tauri 或 Electron」另起了一个隔离的目录，不与 Android 工程共享任何配置。

## 跑起来

```bash
cd desktop-calendar
npm install

npm run dev          # 浏览器里开发，http://localhost:5173
npm run build        # 类型检查 + 产出 dist/
npm run tauri dev    # 以桌面应用启动（982 × 622 固定窗口）
npm run tauri build  # 打安装包
```

浏览器模式下数据存 `localStorage`；Tauri 模式下存应用数据目录里的 `calendar.json`
（Windows 是 `%APPDATA%\com.local.calendar\calendar.json`）。

## 拿一个能直接运行的版本

### 路线一：单文件 HTML（最快，零安装）

```bash
npm run build:single     # 产出 dist-single/index.html，约 220 KB
```

JS 与 CSS 全部内联进这一个文件，改个名字双击就能用浏览器打开，不联网也能跑，
数据存在浏览器的 localStorage 里（`file://` 下已验证可读写、刷新后不丢）。
适合快速试功能。代价是它是一个浏览器标签页，不是独立窗口，也没有系统通知。

### 路线二：真正的安装包（GitHub Actions）

Tauri 的安装包必须在目标系统上编译（Windows 要 MSVC 链接器），所以走 CI：

仓库 → **Actions** → **Build desktop calendar** → **Run workflow**，
跑完在该次运行的 **Artifacts** 里下载：

| 产物 | 内容 |
|---|---|
| `本地日历-windows` | `.msi` 与 `-setup.exe` 安装包 |
| `本地日历-macos-apple-silicon` | `.dmg`（Apple Silicon） |
| `本地日历-linux` | `.deb` 与 `.AppImage` |
| `本地日历-单文件HTML` | 上面那个单文件，顺手一起出 |

Windows 那份解压后有两个文件，任选一个：

- `LocalCalendar_0.1.0_x64-setup.exe` —— NSIS 安装程序，装完开始菜单和桌面都有快捷方式
- `LocalCalendar_0.1.0_x64_en-US.msi` —— MSI 包，适合走组策略批量部署

安装包**没有做代码签名**，所以 Windows 会弹 SmartScreen（「更多信息」→「仍要运行」），
macOS 会被 Gatekeeper 拦（右键 →「打开」，或 `xattr -d com.apple.quarantine <路径>`）。
要消掉得自备签名证书。

产物保留 90 天。

## 收集箱

右侧栏底部常驻一个收集箱，就是原先躲在底栏抽屉里的「无期限」条目 ——
把它扶正成一个能用的暂存区，而不是再造一个并行的「工作台」概念：

- **输入框回车，或点右侧的 `+`** —— 建一条没有日期的任务
- **行尾的垃圾桶** —— 删除这条（可撤销）
- **把条目拖到月视图某一天** —— 给它安排日期
- **把日历上的条目拖回收集箱** —— 取消日期，先放一放（会弹可撤销的提示条）
- 双击或右键条目打开编辑窗

拖动时收集箱整块会变强调底色 + 虚线上边框，落点明确。
只有带日期的条目才会触发这个落点反馈，本来就在收集箱里的拖回来是空操作，
不会污染撤销栈。

底栏原来那个可展开的「无期限」抽屉已经去掉，只留一个计数 —— 内容常驻可见，
不需要再点开一层。

### Windows 上的拖拽

窗口配置里 `dragDropEnabled` 必须是 `false`。Tauri 默认接管系统级文件拖放，
而这在 Windows 上会**吞掉网页内部的 HTML5 拖拽** —— 表现为浏览器里拖得动、
装成桌面应用就拖不动（收集箱拖到日期、条目拖动改期都会失效）。
Tauri 自己的字段注释写明了这一点：*"Disabling it is required to use HTML5 drag
and drop on the frontend on Windows."*

### 输入法

所有「回车提交」的地方都要避开输入法合成期。用中文输入法打字时，确认候选词的
那次 Enter 同样会以 keydown 送到页面，并带 `isComposing = true`，此时输入框里
还是空的 —— 不判断就会出现「按了回车什么也没发生，字随后才出现」。
`src/lib/keys.ts` 的 `isSubmitEnter` 负责这件事，收集箱、搜索框、分组改名、
新增分组，以及全局的「弹窗内回车保存」都走它。

后者尤其要紧：不加判断的话，在编辑窗标题里用中文输入按回车确认候选词，
会直接用半截标题保存并关窗。

## 数据与长期使用

日程存在 `%APPDATA%\com.local.calendar\calendar.json`，窗口位置存在同目录的
`window.json`。都是本机上的普通文件：

- 关机重启不丢，升级程序不影响，卸载程序默认也不会删
- 不联网、不上传、不需要账号
- 备份或换机器：把 `calendar.json` 复制走，放到新机器同一位置即可

齿轮菜单里有**开机自启**开关（`tauri-plugin-autostart`）。真实状态以系统启动项为准，
不落我们自己的存档，启动时读一次，免得用户在系统设置里改过之后两边对不上。

齿轮菜单底部有**清空所有条目**：一次删掉全部日程与任务，**分组、归档、各项设置都保留**，
并且走撤销栈，误点了可以撤销。用来从试用数据切到真实使用。

注意别用「删掉 calendar.json」来清空 —— 读不到文件会回落到种子数据，
反而把 27 条示例条目带回来。

**还缺的**：没有自动备份、没有自动更新、提醒只存字段不会真的弹通知、没有 .ics 导入导出。

两处，内容各自服务于不同场景：

## 分组（项目）管理

顶栏的分组图例就是管理入口：

- **左键点一下** —— 切换该分组在月视图与右侧栏的显隐（隐藏时色点变空心）
- **右键点一下** —— 打开分组编辑浮层：改名、换色、「只看这组」、删除
- **图例末尾的虚线 `+`** —— 新建分组

四个预置分组（学业 / 中信实习 / 中控项目 / 求职）只是**首次运行的默认数据**，
和自建分组完全一样，可以随意改名、换色、归档、删除。

### 归档

项目做完了但不想删，用**归档**（编辑浮层里，在删除左边）：

- 从图例移走 —— 图例不会随着项目越攒越多
- 它的条目不再出现在月视图和右侧栏
- **数据一条没删**，搜索仍然搜得到
- 齿轮菜单 →「已归档分组」可以看到每个归档项目还有多少条目，一键恢复

归档和删除的区别：归档是收起来，分组和归属都留着；删除是真的把分组去掉，
组内条目要另外决定去向。做完的项目用归档，建错的分组才用删除。

改名会同步更新所有条目的分组字段与显隐记录，不会留下孤儿条目。

**删除分组时，组内条目由你决定去向**（空分组直接删，不多问一步）：

| 选项 | 结果 |
|---|---|
| 转为未分组 | 条目保留，落到「未分组」 |
| 移到另一个分组 | 条目保留，整批并入所选分组 —— 项目合并 / 收尾时最常用 |
| 连同条目一起删除 | 条目一并删掉（红色标注） |

三种都走撤销栈，选错了点提示条上的「撤销」即可。

图例里还有一项灰色的**「未分组」**，只在确实存在未分组条目时出现，
用来显隐这批没有归属的条目 —— 否则删完分组后它们就没法管理了。

编辑弹窗「所属日历」下拉里的新增分组入口保留，两条路写的是同一份数据。

## 窗口行为

窗口是**无边框透明**的 —— 面板自带 12px 圆角、阴影和右上角按钮，本来就是照无边框设计的。
顶栏（左侧一组、中间图例、整条栏的空白处）是拖拽区，按住可以拖动窗口。
首次启动自动摆到屏幕右下角，之后记住你放的位置。

### 托盘

应用常驻**通知区域的托盘图标**：

- **左键单击图标 = 把窗口带到眼前**（显示、脱离底层、夹回屏内、取得焦点）。
  这个动作**不做任何 toggle 判断**，无论当前是什么状态，点一下就能看到窗口。
- 右键菜单：显示日历 / 隐藏到托盘 / 吸附到右下角 / **重置窗口（找不到时用）** / 退出
- 面板右上角的 `×` 是**隐藏到托盘**，不是退出；退出走托盘菜单

「重置窗口」是卡住时的退路：清掉记住的位置、关掉桌面模式（并写回 `calendar.json`，
否则下次启动又会沉下去）、吸附到右下角并拿到前台。

### 齿轮菜单

**桌面模式** —— 窗口压到所有窗口之下、并从任务栏隐去，像桌面小组件一样贴在桌面上。
点托盘图标可以随时把它叫到前面，点别处后它自己沉回桌面层。

**面板大小** —— `−` / `+` 在 60% 到 120% 之间调档。整块面板等比缩放，
窗口尺寸同步变成 `982 × 缩放` by `622 × 缩放`。

**吸附到** —— 左上 / 右上 / 左下 / 右下一键归位，按显示器**可用区**（`work_area`）计算，
不会被任务栏压住，四边各留 16px。

缩放的实现是给面板整体套 `transform: scale()`，而不是改成流式布局 —— 这样交接文档里
那些定死的数值（单元格内边距、浮卡 248px、批量条 580px、各处夹取边界）全部原样成立。
代价是锚点换算要除掉缩放系数，见 `CalendarPanel.tsx` 的 `anchorOf` / `toPanel`。

### 手动恢复

万一窗口怎么都找不到，关掉进程后编辑
`%APPDATA%\com.local.calendar\calendar.json`，把 `"desktopMode"` 改成 `false`，
并删除同目录的 `window.json`（那里存的是窗口位置）。日程数据不受影响。

### 一个限制

桌面模式是「压在最底层的窗口」，**不是壁纸层**：按 Win+D「显示桌面」时它会跟着被收起。
要做到连「显示桌面」都影响不了，得用 Windows 的 WorkerW 父窗口那套 —— 代价是窗口变成
桌面的子窗口后，鼠标与键盘输入的路由会变得不可靠，对这种要勾选、拖拽、打字的面板
不划算，所以没有采用。

浏览器里跑的时候，桌面模式、吸附、托盘都不显示（没有窗口的概念），面板大小仍可调。

## 目录

```
src/
  types.ts            条目 / 草稿 / 锚点等类型
  constants.ts        面板尺寸、分组识别色、提醒选项、临期分组定义
  lib/
    date.ts           纯日期运算，全部走 UTC 午夜避开夏令时
    color.ts          分组徽章底色（该色 12%）
    item.ts           显示时间、去时间前缀、月视图 tooltip
  store/
    reducer.ts        全部状态与写操作 + 撤销栈
    selectors.ts      派生数据（可见性、搜索、底栏统计…）
    context.tsx       Provider，负责读盘与防抖落盘
    persistence.ts    存储适配器：Tauri 文件 / localStorage
    seed.ts           示例数据
  hooks/
    useRangeSelect.ts 横拖框选
    usePanelDismiss.ts 点外部关闭
    useGlobalKeys.ts  ←/→、Enter、Esc
    useToastTimer.ts  提示条 5 秒自动消失
  components/         每个屏 / 浮层一个组件，配套 *.module.css
  styles/
    tokens.css        三套主题的 CSS 变量（全局）
    base.module.css   跨组件复用的按钮、下拉、复选框、胶囊开关
src-tauri/            Rust 外壳，两个命令：load_state / save_state
```

状态管理用 `useReducer` + Context，没引第三方状态库。所有写操作都走 reducer 里的
`commit()`，它在改动前压一份快照进撤销栈（上限 20 步）。

颜色一律取 `tokens.css` 里的变量，组件里没有主题外的写死颜色 —— 唯一例外是强调色块上的
文字固定 `#FFFFFF`，以及不随主题变化的分组识别色和四个临期分组色。

## 与原型的差异

交接文档要求高保真 1:1，视觉数值（尺寸、间距、圆角、字号、三套主题色）都照表实现。
下面这些是有意偏离的地方：

| 项 | 原型 | 这里 | 原因 |
|---|---|---|---|
| 今天 | 写死 `2026-09-12` | 取本机当天 | 产品不能把某一天钉死 |
| 示例数据日期 | 写死 `2026-09-xx` | 相对今天的偏移，疏密分布不变 | 否则换一天跑起来全是过期条目 |
| 悬停态 | React state 存 `hoverRow`，重渲染整栏 | CSS `:hover` | 视觉一致，少一次重渲染 |
| 今天 | 只有日期数字带圆形浅底 | 整格淡强调底 + 四周 1.5px 虚线框，日期数字圆形高亮保留 | 原来在一屏 42 格里不够跳出来 |
| 分组 | 四个写死的内置分组 + 用户新增的 `customGroups`，只能加不能改删 | 统一成一份可增删改的 `groups`，图例右键即可编辑 | 原型没有分组管理入口 |
| 每周重复 | 只在记录上存 `repeatOn` / `repeatWeeks` 两个标记，并不真的生成 | 保存时展开成 N 条共用 `repeatId` 的独立记录 | 文档与界面文案都写的是「将生成 N 条独立日程，可整组删除」 |
| 删除整组 | 按「标题相同且带重复标记」匹配 | 优先按 `repeatId` 匹配，示例数据没有该字段时才退回按标题 | 按标题匹配会误删同名的其他日程 |
| 撤销快照 | 只含 `tasks` + `hidden` | 另含 `nextId` 与 `customGroups` | 原来撤销后 `nextId` 不回退，新建的 id 会和被撤销的记录撞上 |
| 设置 / 配色 / 无期限三个菜单 | 只能靠再点一次或 Esc 关 | 点外部也关（触发按钮打了 `data-menu`，不会关了又立刻开） | 桌面端的常规预期 |
| 月网格文字 | 可被鼠标选中 | `user-select: none` | 横拖框选时会顺手选中日期数字 |

文档里「做成真实产品时建议改动」那几条的落地情况：

- **已做** —— 撤销栈快照修正、重复日程分组键。
- **保持原型形态** —— 跨天日程仍是逐日拆成多条同 `spanId` 的记录（改成一条 `start`/`end`
  横跨渲染要重做月网格的布局，超出本次范围）；时间仍是 `date` + `time` 两个字符串，
  没换成 ISO 时间戳 + 时区。
- **未实现** —— 提醒只存字段，没接系统通知与后台唤醒；没做 .ics 导入导出。
  这三项文档本身也列在产品化改动里，不属于本次要还原的界面与交互。

持久化目前是 JSON 文件。换 SQLite 只需要改 `src-tauri/src/lib.rs` 里那两个命令，
前端的 `CalendarStorage` 接口不用动。

## 验证情况

`npm run build`（含 `tsc`）通过。用 Chromium 实跑过一轮，确认：

- 面板实际尺寸 982 × 622（980 + 1px 描边），月网格 42 格
- 点日期格弹日详情浮卡，靠右边界时正确翻到格子左侧
- 浮卡里点条目开编辑弹窗；分组下拉、内嵌月历、双列时分选择器都能展开
- 横拖框选出选区描边与浮标，松手浮出批量操作条；「每天各一条」建出 4 条并弹提示条，
  点撤销后 4 条全部回退
- 拖条目到别的日期能改期并弹提示条
- 右键菜单、搜索下拉、三套主题切换、重载后主题与数据仍在
- 焦点在输入框里、或鼠标移出面板时，←/→ 都不翻月；移回面板内才翻
- 无 console 报错

单文件版在 `file://` 下另测过一轮：渲染正常、localStorage 可读写、新建的条目与
切换的主题在刷新后都还在。

`src-tauri/` 无法在开发容器里编译（缺 webkit2gtk / gdk-3.0），改由 CI 验证，
三个平台全部构建成功：

| 平台 | 产物 |
|---|---|
| windows-latest | `LocalCalendar_0.1.0_x64_en-US.msi`、`LocalCalendar_0.1.0_x64-setup.exe` |
| macos-latest | `.dmg`（Apple Silicon） |
| ubuntu-22.04 | `.deb`、`.AppImage` |

也就是说 Rust 代码、`tauri.conf.json` 与图标格式都已被真实打包链验证。
（首轮构建曾因图标清单里缺 `.ico` / `.icns` 而需要修复，现已补齐。）
